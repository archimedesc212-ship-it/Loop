# LOOP lyrics, annotations and immersive player DBMS demo

## Architecture

The feature is integrated into the existing React/Vite player and Express/MySQL architecture.

- `ImmersivePlayer.jsx` reads the existing `usePlayer()` state. Opening lyrics never creates a second player or interrupts playback.
- `VisualizerCanvas` uses a Web Audio `AnalyserNode` only when it can attach to a same-origin HTML audio element. It analyses frequency and waveform data and draws a low-density visual layer.
- YouTube and Apple Music embeds are cross-origin. Their audio samples and playback clock are not exposed to LOOP; the UI explicitly reports this limitation and does not fabricate audio-reactive motion or lyric synchronization.
- Lyrics are never generated. The API accepts only rights-confirmed user-provided or licensed lyrics.
- Annotations and song notes are private to their author by default.

## Database model

Migration `0010_lyrics_and_annotations.sql` adds:
- `song_lyrics`: one rights-confirmed lyric set per song and language.
- `lyric_lines`: timestamped lyric lines, ordered by line number.
- `lyric_annotations`: user-owned annotations attached to a lyric line.
- `user_song_notes`: one persistent note per user/song pair.

The existing normalized `users`, `songs`, `artists`, `albums`, `playlists`, `playlist_songs`, `listening_history` and `user_likes` tables are reused. In particular, `user_likes` remains the single source of truth for favourites; no duplicate favourites table is created. The migration also creates `v_song_lyric_annotation_summary` for relational reporting. Existing DB transactions, constraints, session authentication and CSRF middleware are reused.

## Apply

From the repository root:

```bash
cp .env.example .env
# Configure the existing MySQL owner/app credentials and set VITE_DEMO_MODE=false.
npm run db:migrate
npm run build
npm test
npm run test:web
```

The migration is additive and checksum-tracked. Do not edit an already-applied migration; use a later migration for future changes.

## API contracts

All routes require the existing authenticated session and inherit input validation, write rate limiting and cookie CSRF protection.

- `GET /api/songs/:id/lyrics` — fetch rights-cleared lines, the caller's private annotations, own note and favourite state.
- `PUT /api/songs/:id/lyrics` — replace a lyric set only with `rightsConfirmed: true`, `sourceType` of `USER_PROVIDED` or `LICENSED`, a source label, and timestamped lines in ascending order.
- `POST /api/songs/:id/lyrics/annotations` — add a private annotation to a line belonging to that song.
- `DELETE /api/lyrics/annotations/:annotationId` — delete only the current user's annotation.
- `PUT /api/songs/:id/notes` — upsert or clear the current user's private song note.

`PUT /lyrics` validates timestamps and inserts/replaces the lyric set and all its lines in one transaction. The `lyric_lines` foreign key cascades old annotations when an authorized lyric owner replaces the lyric set. An annotation cannot be attached to a line from a different song.

## Faculty demonstration

1. Sign in through LOOP and play a catalogue song. Open Now Playing; confirm the request to `/api/songs/:id/lyrics` in browser Network tools.
2. Submit rights-cleared lyrics from the authenticated API client with `rightsConfirmed: true`. Do not copy lyrics from an unlicensed source.
3. Select a line in Now Playing and save a private annotation. Reload the player and confirm it is still present.
4. Save a song note, refresh, and confirm it persists.
5. Inspect the real MySQL rows using `database/workbench/lyrics_annotations_demo.sql`. Query 1 demonstrates the view and aggregates; query 2 demonstrates joins; query 3 joins existing favourites with user notes; query 4 demonstrates annotation ownership/privacy.
6. Run the transaction example with real IDs. The row is visible inside the transaction and disappears after `ROLLBACK`.
7. Demonstrate constraints with `SHOW CREATE TABLE`; the unique `(user_id, song_id)` key prevents duplicate notes and foreign keys reject orphan lyric/annotation rows.

No query results are hard-coded in this documentation: result sets are generated by the configured MySQL database.
